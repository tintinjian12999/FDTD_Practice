# One-Dimensional FDTD Program Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a book-comparable Program 3.1 executable and a reusable,
validated one-dimensional free-space FDTD solver with CLI, CSV output, plots,
and GIF animation.

**Architecture:** Keep the book reproduction independent and monolithic while
placing the production Yee-grid update in an opaque C library. A native C CLI
owns parameter parsing and output, and a strict Python module owns
visualization.

**Tech Stack:** C17, GCC 15.2, CMake 4.4, Ninja 1.13, CTest, Python 3.12,
NumPy 2.5, Matplotlib 3.11, Pillow, Pytest 9, native Windows PowerShell.

## Global Constraints

- Work on `feat/fdtd-1d`, based on `feat/windows-c-fdtd-environment`.
- Keep all source-code comments in English.
- Keep every C and Python function at or below 40 physical lines.
- Compile with `-Wall -Wextra -Wpedantic`; final Debug verification also uses
  `UFDTD_WARNINGS_AS_ERRORS=ON`.
- Use `double` for fields, coefficients, source values, time, and position.
- Require finite values and \(0<S_c\le1\).
- Keep the standalone Program 3.1 path independent from the reusable core.
- Never modify `base` or `cpp_env`; use only `ufdtd-c`.
- Do not add firewall rules, system-wide packages, or a Git remote.
- Do not include GUI work in this branch.
- Use `python -m` for repository Python modules.
- Preserve all existing smoke and environment tests.

## File Structure

- Create `examples/ch03/book_1d_bare_bones.c`: Program 3.1 reproduction.

```python
import subprocess

import numpy as np


ROOT = Path(__file__).parents[1]
EXECUTABLE = ROOT / "build" / "debug" / "book_1d_bare_bones.exe"


def test_book_program_reproduces_delayed_gaussian() -> None:
    result = subprocess.run(
        [EXECUTABLE],
        cwd=ROOT,
        capture_output=True,
        text=True,
        check=False,
    )

    assert np.all(np.isfinite(samples))
    assert int(np.argmax(samples)) == 80
    assert abs(float(samples[80]) - 1.0) <= 1.0e-12
```

```c
enum FDTD1DMode { FDTD1D_HARD_PMC, FDTD1D_ADDITIVE_ABC };
enum FDTD1DScale { FDTD1D_NORMALIZED, FDTD1D_SI };
enum FDTD1DStatus {
    FDTD1D_OK,
    FDTD1D_INVALID_ARGUMENT,
    FDTD1D_ALLOCATION_FAILED,
    FDTD1D_NUMERIC_ERROR,
    FDTD1D_FINISHED

struct FDTD1DConfig {

    enum FDTD1DScale scale;
    size_t grid_size;
    size_t time_steps;
    size_t source_index;
    size_t probe_index;

enum FDTD1DStatus fdtd1d_validate_config(

);
struct FDTD1D *fdtd1d_create(
    const struct FDTD1DConfig *config, char *error, size_t error_size
);
```

- [ ] **Step 4: Implement allocation and destruction**

```c
struct FDTD1D {

```

Allocate both arrays with `calloc(grid_size, sizeof(double))`. On partial
allocation failure, release all owned memory and return `NULL` with status text.
`fdtd1d_destroy(NULL)` is a no-op.

- [ ] **Step 3: Implement the update sequence**

Split implementation into focused helpers:

```c
static void update_magnetic(struct FDTD1D *simulation);
static void update_electric_hard(struct FDTD1D *simulation);
static void update_electric_interior(struct FDTD1D *simulation);
```

For additive ABC, save old boundary and neighbor values before updating the
interior, then use:

```c
const double coefficient = (courant - 1.0) / (courant + 1.0);
new_left = old_left_neighbor
    + coefficient * (new_left_neighbor - old_left);
new_right = old_right_neighbor
    + coefficient * (new_right_neighbor - old_right);
```

Increment `current_step` only after a finite completed step.
