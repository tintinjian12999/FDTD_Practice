# One-Dimensional FDTD GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a responsive native Windows GUI that configures the existing C
solver, runs it through the CLI boundary, and displays strictly validated probe
and field results.

**Architecture:** Keep validation and command construction in a pure model,
subprocess ownership in a thread-safe runner, and Matplotlib state in a focused
plot component. The Tk application coordinates these units but never performs
FDTD updates or parses output files itself.

**Tech Stack:** Python 3.12, Tk 8.6, ttk, Matplotlib 3.11, NumPy 2.5, Pillow
12, Pytest 9, C17 `fdtd1d.exe`, native Windows PowerShell.

## Global Constraints

- Work on `feat/fdtd-1d-gui`, based on the verified `feat/fdtd-1d`.
- Keep the C CLI as the only numerical implementation.
- Load run data only through `scripts.visualize_fdtd1d.load_run`.
- Use `subprocess.Popen` with an argument list, `shell=False`, and no console.
- Never access Tk widgets from a worker thread.
- Permit only one active solver process and terminate only that owned process.
- Preserve the last valid display after validation, execution, or loading failure.
- Require confirmation before replacing recognized output files.
- Keep every new Python function or method at or below 40 physical lines.
- Keep all source-code comments in English.
- Add no runtime dependency beyond the existing `ufdtd-c` environment.
- Use test-first RED/GREEN cycles and commit each independently testable unit.

## File Structure

- Create `gui/__init__.py`: package marker.
- Create `gui/fdtd1d_model.py`: pure parameters, validation, commands, paths.
- Create `gui/fdtd1d_runner.py`: process lifecycle and cancellation.
- Create `gui/fdtd1d_plot.py`: snapshot preparation and embedded plots.
- Create `gui/fdtd1d_gui.py`: Tk widgets and application orchestration.
- Create `tests/test_fdtd1d_gui_model.py`: parameter and discovery tests.
- Create `tests/test_fdtd1d_runner.py`: real process lifecycle tests.
- Create `tests/test_fdtd1d_plot.py`: pure snapshot preparation tests.
- Create `tests/test_fdtd1d_gui.py`: import, defaults, and check-mode tests.
- Modify `scripts/verify.ps1`: add noninteractive GUI environment check.
- Modify `README.md`: bilingual GUI launch and workflow.
- Modify `CHANGELOG.md`: GUI release record.

### Task 2: Thread-Safe Solver Process Runner

**Files:**
- Create: `gui/fdtd1d_runner.py`
- Create: `tests/test_fdtd1d_runner.py`

**Interfaces:**
- Produces:

```python
@dataclass(frozen=True)
class RunResult:
    returncode: int
    stdout: str
    stderr: str
    cancelled: bool


class SimulationRunner:
    @property
    def running(self) -> bool: ...
    def run(self, command: list[str], cwd: Path | None = None) -> RunResult: ...
    def cancel(self) -> bool: ...
```

- [ ] **Step 1: Write failing runner tests**

Run the real Debug solver with a small valid command and assert return code 0,
empty stderr, and the three output files. Run a Python child that writes to
stdout/stderr and exits 7, asserting exact capture and cleanup.

For cancellation, start this child in a test thread:

```python
command = [
    sys.executable, "-c",
    "import time; print('started', flush=True); time.sleep(30)",
]
```

Poll `runner.running`, assert a second `run` raises `RuntimeError`, call
`cancel`, join within five seconds, and assert `cancelled` is true. Assert
`cancel()` returns false when idle.

- [ ] **Step 2: Verify RED**

Expected: collection fails because `gui.fdtd1d_runner` does not exist.

- [ ] **Step 3: Implement runner ownership**

Use one `threading.Lock`, `_process: Popen[str] | None`, and
`_cancel_requested`. Set `creationflags=subprocess.CREATE_NO_WINDOW` on
Windows and zero elsewhere. Register the process while holding the lock,
release the lock during `communicate`, and clear ownership in `finally`.

`cancel` obtains the current owned process under the lock, sets the flag, then
calls `terminate` outside the lock. It never searches for other processes.

- [ ] **Step 4: Verify GREEN and commit**

Run runner tests three times to expose races, then run model and CLI tests.


- [ ] **Step 4: Implement scale, run, and queue flow**

`_parameters` converts Tk variables to `SimulationParameters`. `_run` validates,
discovers the solver, confirms recognized output replacement, disables mutable
controls, starts progress, and launches a daemon worker. The worker only puts a
`RunResult` on `queue.Queue`; `_poll_results` runs on Tk via `after`.

On success, call:

```python
metadata, probe, snapshots = load_run(output_directory)
self.plot.show_run(metadata, probe, snapshots)
```

Catch `ValueError`/`OSError` on the Tk thread, log the message, restore controls,
and do not call `show_run`. Cancellation calls only `self.runner.cancel()`.

- [ ] **Step 5: Implement snapshot controls and close behavior**

Connect scale variable traces, slider command, previous/next, and play/pause.
Update slider range after a valid run. Closing while active requires
`messagebox.askyesno`; accepted close cancels and polls until idle before
destroying the root.

- [ ] **Step 6: Implement check and main modes**

`--check` imports Tk and TkAgg, resolves the solver, validates defaults, and
builds a command without creating `Tk`. No arguments create the root,
application, and main loop. Other arguments print usage to stderr and return 2.
